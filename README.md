# 脆自動助手（Threads 自動助手）

在自己電腦上跑的 Threads（脆）經營工具。用 AI 寫文並排程發文，用關鍵字「海巡」找相關貼文並自動留言。支援多帳號，每個帳號用獨立的瀏覽器設定檔，登入一次就會記住。

> 所有資料（帳號登入狀態、貼文、留言、API 金鑰）都只存在本機 `data/` 資料夾，不會上傳到任何第三方伺服器。只有 AI 寫文時會把提示詞送給你選的 AI 服務。

## 功能總覽

| 功能 | 說明 |
|---|---|
| **多帳號** | 每個帳號一個獨立的 Chrome 設定檔，cookie 互不干擾，登入一次就會記住 |
| **自動發文** | 設定主題和風格，AI 每天在指定時段內隨機挑時間發 N 篇。可選「自動發出」或「審核後才發」 |
| **手動排程** | 自己寫或請 AI 幫寫，可附圖片或影片（最多 10 個），立即發或排定時間發 |
| **發文紀錄** | 所有貼文的狀態（已發佈、排程中、待審核、失敗），可依來源篩選，並附 Threads 貼文連結 |
| **自動海巡** | 依關鍵字搜尋最新或最相關的貼文，可依讚數門檻篩選，AI 判斷適不適合留言並寫好留言 |
| **留言紀錄** | 留言審核、修改、AI 重寫、取消、重試，送出結果一目了然 |
| **送出佇列** | 每個帳號每小時最多 N 則，間隔自動隨機分散，模擬真人節奏 |
| **防重複** | AI 寫的內容會和近期內容比相似度，太像就重寫；海巡看過的貼文不會再看 |
| **執行紀錄** | 總覽頁即時顯示背景工作的每一步與錯誤 |

## 系統需求

- **作業系統**：Windows 10 / 11（主要支援平台）
- **Python**：3.10 以上（開發環境為 3.13）
- **瀏覽器**：Google Chrome 或 Microsoft Edge（程式會自動尋找）
- **AI 服務**（四選一，見 [AI 服務設定](#ai-服務設定)）

## 安裝與啟動

### 一鍵啟動（建議）

雙擊 **`啟動.bat`**。

第一次執行會自動安裝缺少的套件（約 1～2 分鐘），之後就直接開啟桌面視窗。啟動器會用 `pythonw` 在背景執行，不會留下黑色主控台視窗。

### 手動啟動

```bash
pip install -r requirements.txt
python main.py
```

程式會在 `127.0.0.1` 上挑一個空的連接埠啟動，並用 pywebview 開啟桌面視窗；如果 pywebview 開不起來，會改用預設瀏覽器打開。

### 套件

| 套件 | 用途 |
|---|---|
| `fastapi`、`uvicorn` | 本機 API 伺服器與網頁介面 |
| `websocket-client` | 透過 Chrome DevTools Protocol 操作瀏覽器 |
| `pywebview` | 桌面視窗 |
| `anthropic` | Claude API |
| `openai` | OpenAI API |

## 第一次使用

1. **設定 AI**：到「設定」選一種 AI 服務並完成登入或填入金鑰，按「測試」確認可用。
2. **新增帳號**：到「帳號」新增，按「開啟瀏覽器登入」，在跳出的專屬瀏覽器裡登入 Threads，然後按「檢查登入」。
3. **設定品牌定位**（選填）：在「設定」填寫帳號的定位、語氣和禁忌，AI 寫文和留言都會參考。
4. **建立自動規則**：到「自動發文」或「自動海巡」設定規則。
5. **啟動**：確認左下角是「自動執行中」。

## 各頁面說明

### 總覽
今日發文數與留言數、排程數、待審核數，以及即時的執行紀錄。

### 帳號
新增、改名或刪除帳號，開啟或關閉該帳號的專屬瀏覽器，檢查登入狀態（會同時抓取 `@使用者名稱`）。

### 自動發文
每個帳號一組規則：

- **主題**：可以填多個，AI 每次挑一個寫
- **風格**：例如「幽默、像朋友聊天」
- **每天篇數**、**發文時段**（開始和結束小時）
- **篇幅**：短、中、長
- **發文方式**：自動發出，或審核後才發（放到「發文紀錄 → 待審核」）
- **固定附圖**（選填）

### 手動排程
左邊撰寫（字數上限 500，符合 Threads 限制），右邊是貼文列表。「AI 幫我寫」可以依主題一次產生 1～5 篇讓你挑。

### 自動海巡
每個任務包含：

- **關鍵字**（可多個）、搜尋「最近」或「最相關」
- **留言風格**、**最低讚數**
- **執行間隔**（分鐘）、**每次最多留言數**
- **留言方式**：自動送出，或審核後才送出
- **附圖**（選填，會改用完整回覆視窗附上）

AI 會先判斷貼文適不適合留言（例如不相關、敏感或純廣告時會略過），適合才寫。

### 發文紀錄
集中顯示自動發文和手動排程的所有貼文：

- **分頁**：已發佈、排程中、待審核、失敗
- **來源篩選**：全部、AI 自動發文、手動排程
- **貼文連結**：發佈成功後會自動到個人檔案頁比對內文，存下貼文網址，點「在 Threads 查看」就能開啟
- **補上連結**：較早發的、沒有連結的貼文，可以在「已發佈」按「補上連結」批次補齊

### 留言紀錄
分頁：待審核、待送出、已送出、失敗、略過或取消。可以修改、AI 重寫、核准（或全部核准）、取消、重試，被略過的貼文也可以選「還是要留言」。

### 設定
AI 服務與模型、每小時留言上限、品牌定位。

## AI 服務設定

| 選項 | 計費方式 | 需要 |
|---|---|---|
| **Claude 訂閱登入** | 用 Claude Pro 或 Max 訂閱額度，不另外計費 | 本機安裝 [Claude Code](https://claude.com/claude-code) CLI |
| **ChatGPT 訂閱登入** | 用 ChatGPT Plus 或 Pro 訂閱額度，不另外計費 | 本機安裝 Codex CLI |
| **Claude API Key** | 依用量計費 | Anthropic API 金鑰 |
| **OpenAI API Key** | 依用量計費 | OpenAI API 金鑰 |

- 訂閱登入：在設定頁按「登入 Claude」或「登入 ChatGPT」，照指示在瀏覽器完成登入。
- 模型清單會自動偵測，可以在設定頁切換。
- AI 回覆格式不對時會自動重試；寫出來的內容和近期內容太像也會重寫。

## 頻率限制與帳號安全

Threads 會偵測機器人行為。程式內建以下保護：

| 項目 | 建議值 | 超過時 |
|---|---|---|
| 每天發文 | ≤ 5 篇 | 超過 15 篇會出現強烈警告 |
| 每小時留言 | ≤ 6 則 | 超過 15 則會出現強烈警告 |

- **隨機化**：發文時間在時段內隨機挑；留言間隔約為 `60 ÷ 每小時上限` 分鐘，再加上隨機變動。
- **模擬真人**：用真實滑鼠事件點擊、逐字輸入，送出前有「閱讀」停頓。
- **一次只做一件事**：背景工作依序執行，同一時間只操作一個瀏覽器。
- **建議**：新帳號先用低頻率跑幾天，或先用小號測試。

## 運作原理

```
┌─────────────┐   HTTP    ┌──────────────┐   SQLite   ┌───────────┐
│ 網頁介面    │ ────────▶ │ FastAPI      │ ─────────▶ │ threads.db│
│ (pywebview) │ ◀──────── │ app/server.py│ ◀───────── │           │
└─────────────┘           └──────────────┘            └─────▲─────┘
                                                            │
                          ┌──────────────┐                  │
                          │ 背景排程      │ ─────────────────┘
                          │ app/worker.py│
                          └──┬────────┬──┘
                   AI 寫文／留言│        │瀏覽器操作
                          ┌────▼───┐ ┌──▼─────────────┐  CDP   ┌──────────────┐
                          │ app/ai │ │app/threads_bot │ ─────▶ │ Chrome（每個 │
                          └────────┘ │  app/cdp.py    │        │ 帳號獨立設定檔）│
                                     └────────────────┘        └──────────────┘
```

**背景排程（`worker.py`）** 是一個常駐執行緒，依序處理：

1. **自動發文規則**：到了下次發文時間，就請 AI 寫一篇，排進貼文表（審核模式則設為待審核）
2. **到點貼文**：發出 `scheduled_at` 已到的貼文，成功後記下貼文網址
3. **海巡任務**：到了間隔時間，就搜尋關鍵字、略過看過的貼文、請 AI 寫留言、排進佇列
4. **留言佇列**：依每帳號每小時上限，送出已核准的留言

**瀏覽器操作（`cdp.py`、`threads_bot.py`）**：不用 Selenium 或 Playwright，直接用 `--remote-debugging-port` 啟動 Chrome，再透過 DevTools Protocol 的 WebSocket 執行 JS、派送滑鼠和鍵盤事件、設定上傳檔案。每個帳號有固定的除錯連接埠和設定檔目錄（`data/profiles/acc_<id>`）。

DOM 選擇器在 `threads_bot.py` 檔頭有完整記錄（2026-11-27 實地確認）。Threads 改版時，主要要調整的就是這個檔案。

```
├── main.py             # 進入點：初始化 DB、啟動 worker 與 API、開視窗
├── requirements.txt
├── app/
│   ├── db.py           # SQLite 結構、自動升級、設定存取、記錄
│   ├── server.py       # FastAPI REST API 與靜態檔
│   ├── worker.py       # 背景排程：自動發文、發文、海巡、留言佇列
│   ├── threads_bot.py  # Threads 網頁操作：登入檢查、搜尋、發文、回覆、找貼文網址
│   ├── cdp.py          # Chrome 啟動與 DevTools Protocol 封裝
│   └── ai.py           # 四種 AI 服務整合、提示詞、相似度檢查
├── web/
│   ├── index.html

└── data/               # 執行時產生，不納入版控（見 .gitignore）
    ├── threads.db
    ├── app.log
    ├── profiles/       # 各帳號瀏覽器設定檔（含登入 cookie）
    └── uploads/        # 上傳的圖片和影片
```

## 資料庫結構

SQLite（`data/threads.db`）。啟動時會自動建表並升級舊版欄位。

| 資料表 | 用途 | 重要欄位 |
|---|---|---|
| `accounts` | 帳號 | `name`、`username`、`logged_in`、`checked_at` |
| `posts` | 貼文 | `text`、`images`、`scheduled_at`、`status`（`pending` / `scheduled` / `sending` / `sent` / `failed`）、`source`（`manual` / `auto`）、`posted_at`、`url` |
| `autopost` | 自動發文規則（每帳號一筆） | `topics`、`persona`、`per_day`、`start_hour`、`end_hour`、`length`、`review`、`next_at` |
| `tasks` | 海巡任務 | `keywords`、`recent`、`mode`（`auto` / `review`）、`interval_min`、`max_per_run`、`min_likes`、`last_run` |
| `comments` | 留言 | `post_url`、`author`、`post_text`、`draft`、`status`（`pending` / `approved` / `sending` / `sent` / `failed` / `skipped` / `rejected`）、`sent_at` |
| `seen` | 海巡看過的貼文 | `(account_id, post_url)` |
| `logs` | 執行紀錄 | `ts`、`level`、`msg` |
| `settings` | 鍵值設定 | AI 服務、金鑰、模型、每小時上限、品牌定位 |

程式中斷時卡在 `sending` 的項目，下次啟動會自動恢復成待發狀態。

## 資料與隱私

- `data/` 有**瀏覽器登入 cookie**、**API 金鑰**和所有內容，已列在 `.gitignore`，**絕對不要上傳或分享**。
- 要搬到新電腦，把整個資料夾（含 `data/`）複製過去就可以。
- 要重設，就關掉程式後刪除 `data/`（所有帳號都要重新登入）。

## 疑難排解

| 問題 | 解法 |
|---|---|
| 「找不到 Chrome 或 Edge」 | 安裝 Google Chrome |
| 帳號一直顯示未登入 | 到「帳號」按「開啟瀏覽器登入」，在**那個視窗**裡登入，再按「檢查登入」 |
| 「找不到『新串文』按鈕」 | 頁面還沒載入完，或 Threads 改版。看 `data/app.log`，並確認 `threads_bot.py` 的選擇器 |
| 發文成功但沒有連結 | 到「發文紀錄 → 已發佈」按「補上連結」；如果提示抓不到使用者名稱，先到「帳號」按「檢查登入」 |
| AI 測試失敗 | 訂閱登入：確認 CLI 已安裝並登入；API：確認金鑰和額度 |
| 留言一直「失敗」 | 貼文可能已刪除或限制回覆，或帳號被限制。先降低每小時上限 |
| 視窗沒出現 | 看 `data/app.log`；也可以用 `python main.py` 在主控台執行，看錯誤訊息 |

## 開發說明

- 前端是原生 JS，改完 `web/` 重新整理視窗就生效；改 `app/` 要重開程式。
- 資料庫升級寫在 `db.init()`，用 `PRAGMA table_info` 檢查欄位，缺了才 `ALTER TABLE`。新增欄位請照同樣模式。
- 所有瀏覽器操作集中在 `threads_bot.py`，UI 文字比對以繁體中文介面為準。
